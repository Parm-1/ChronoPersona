# Evaluations

Evaluation items will be stored in versioned registries under `evaluations/registry/`.

Each item should record:

- stable item ID and version;
- outcome family and construct;
- development or confirmatory split;
- prompt and response format;
- explicit date-cue status;
- scoring method, rubric, and directionality;
- provenance and rights status;
- known confounds;
- registry hash once frozen.

The first registry does not exist yet. It must be designed, audited for temporal cues, and frozen before pilot outputs are generated.
