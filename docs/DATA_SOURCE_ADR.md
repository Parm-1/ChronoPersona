# Data Source ADR

**Date:** 2026-08-17  
**Status:** provisional qualification; no bulk corpus acquisition authorized  
**Decision class:** Stage 0 naturalistic source architecture

## Decision

Use the following provisional source-family architecture for metadata and small-sample qualification:

- **Source A:** Wikimedia article-revision added-text deltas.
- **Source B:** paused. The former provisional Stack Exchange panel requires
  explicit authorization or a later independently reviewed compliant access
  contract; D-042 audits alternate non-Q&A candidates without selecting one.
- **Source C:** single-version, item-level CC0 or CC BY arXiv source text from narrowly selected descriptive-science strata.
- **Predeclared backup C:** version-bounded item-level CC0 or CC BY PMC Open Access full text.
- **Rejected headline source:** Federal Register/GovInfo official documents, retained only as a possible direct-exposure boundary condition.

This is not a final data freeze. Each assignment must survive metadata-volume, timestamp, version-integrity, rights, source-independence, authorship, direct-exposure, and storage audits before text acquisition or model training.

The machine-readable decision is in:

`artifacts/manifests/SOURCE_REGISTRY.json`

## Why this architecture

CSTG requires more than three datasets. It requires three independent ways that human text from an era enters the model.

The provisional families differ in:

| Family | Production process | Contributor population | Primary genre | Native time object |
|---|---|---|---|---|
| Wikimedia A | collaborative revision and editorial process | encyclopedia editors | expository reference prose | revision that introduced a text span |
| Stack Exchange B | question, answer, voting, and moderation process | community users | questions and practical explanations | initial post-version creation |
| arXiv C | moderated scholarly submission process | research authors | scientific exposition | first and only submission version |
| PMC backup C | journal/manuscript deposit pipeline | biomedical authors and publishers | journal article prose | publication/version record |

This process diversity is more important than superficial domain diversity. Two collections generated by the same platform, editorial process, or contributor population would not provide a credible held-out-source confirmation.

## Selection rules

Source selection is performed before behavioral outcomes.

The final A/B/C decision may use:

- timestamp semantics and confidence;
- coverage and extractable volume in both era windows;
- item-level rights and attribution;
- version integrity;
- human-authorship confidence;
- source and contributor independence;
- topic and event concentration;
- duplicate and cross-source overlap;
- direct exposure to evaluation constructs;
- storage and extraction feasibility.

It may not use:

- which source creates a larger behavioral effect;
- which source agrees with an expected temporal direction;
- which source improves a preferred paper narrative;
- model outputs from source C;
- source-C information for item, dose, threshold, hyperparameter, or mechanism selection.

## Source A — Wikimedia added-text deltas

### Scientific role

Wikimedia supplies collaboratively authored descriptive prose under a revision-native process distinct from both community question answering and scholarly publication.

### Required representation

Do not treat full page snapshots as independent documents. A page history repeatedly contains inherited text, so naive snapshot training would massively overweight older passages.

The required unit is a retained **added-text span**:

1. identify a native page revision and its parent;
2. reconstruct normalized article text for both;
3. calculate deterministic added spans;
4. detect reverts and reintroductions;
5. exclude templates, references, navigation, lists, category text, boilerplate, and copied/imported material where lineage is unresolved;
6. retain only prose additions that survive the frozen persistence rule;
7. preserve page, revision, parent, contributor, bot, timestamp, license, transformation, and hash lineage.

A passage reintroduced after a revert is not automatically a new independent training example.

### Timestamp

Use the native revision timestamp that introduced the retained span. Do not use:

- current page timestamp;
- dump generation time;
- archive-capture time;
- event dates mentioned in the prose.

### Historical selection leakage

Selecting pages from their current categories can use later taxonomy to construct earlier corpora. Final topic strata must therefore use one of:

- category membership demonstrably available at the eligible revision;
- a frozen text classifier trained without model behavioral outcomes or source C;
- explicit page identifiers selected from a preregistered external taxonomy whose historical applicability is justified.

The classifier may identify disallowed direct-exposure topics. It must not select text because it appears to contain a desired early/late behavioral direction.

### Rights

Wikimedia text is offered for reuse under project-specific free licenses with attribution and share-alike obligations. Page histories and imported-text notices are part of the rights lineage. Non-text media and imported passages can have different terms.

For this project:

- text-only article prose is the default;
- attribution locators remain in the manifest;
- raw corpus and model release remain separate reviewed decisions;
- this ADR does not conclude that a trained model is or is not an adapted work under the source license.

### Main blockers

- full history size;
- revision reconstruction complexity;
- reverts, vandalism, bots, mass imports, and deleted revisions;
- future-derived page/category selection;
- broad direct exposure to institutional and procedural topics;
- attribution and share-alike treatment.

### Qualification decision

**Qualified with redesign.** Continue metadata and bounded-sample work only.

## Source B — initial Stack Exchange post versions

### Scientific role

Stack Exchange supplies user-authored questions and answers produced under a voting and moderation process. It is structurally independent from Wikimedia and arXiv, although contributors and external source material can overlap.

### Required representation

Do not use the latest `Posts` body as historical text. A post created in the early window can contain edits made years later.

For every retained post:

1. recover the initial title/body from `PostHistory` or an equivalent authoritative version record;
2. preserve post, version, author, site, creation, license-version, edit, migration, and deletion lineage;
3. strip markup and quotations through a versioned transformation;
4. exclude quoted blocks, code, links, signatures, boilerplate, automated posts, spam, and uncertain imported text;
5. keep question and answer types as separate strata;
6. cluster cross-post quotations and syndicated text.

### Site panel

The final site panel must be frozen before model outcomes and must have continuous, sufficient coverage in both windows.

The first-pass exclusion set includes sites centered on:

- programming and software engineering;
- cybersecurity;
- law and politics;
- medicine and health;
- academia and research practice;
- statistics, AI, data science, and economics;
- workplace policy;
- skepticism, misinformation, and evidence adjudication;
- interpersonal advice or governance domains that directly instantiate the primary constructs.

The remaining sites still require topic-level filtering. “Nontechnical” does not mean “no procedural reasoning.”

### Timestamp

Use the native creation timestamp of the initial post version. Do not use current edit time or dump creation time.

### Rights

Stack Exchange contribution licenses vary by contribution date. The applicable Creative Commons BY-SA version, author/attribution locator, site, and post version must be recorded per item.

Use the official data dump or API under their applicable terms. Do not systematically scrape rendered public pages.

### Main blockers

- date-dependent license versions;
- historical body reconstruction;
- deleted-post and survivorship bias;
- site launches, closures, migrations, and changing community composition;
- direct advice and procedural exposure;
- share-alike and attribution treatment;
- quotations and copied external text.

### Qualification decision

**Qualified with redesign.** Continue dump-metadata and initial-version-recoverability work only.

## Source C — single-version permissively licensed arXiv descriptive science

### Scientific role

arXiv is held out because its production process, contributor population, and genre differ materially from A and B. It is not used to construct the expected temporal direction.

### Why single-version records

The metadata API provides version dates, while current bulk source can represent the latest submitted version. For a paper with later revisions, assigning the full current source to its first submission date could introduce future text.

The first confirmatory design therefore retains only papers that:

- have exactly one version;
- were submitted inside the eligible era window;
- carry item-level CC0 or CC BY licensing;
- belong to frozen descriptive-science categories;
- pass domain-exposure and direct-methodology filters;
- have an immutable source hash from an approved retrieval path.

Multi-version papers remain excluded unless a version-specific historical source path is verified.

### Category strategy

The first-pass category exclusions include:

- artificial intelligence and machine learning;
- statistics and data science;
- decision, control, and optimization methods;
- economics, quantitative finance, and social science;
- computer and information security;
- software and programming;
- governance, policy, law, and institutional design;
- misinformation, calibration, source reliability, survey methods, and evaluation methodology.

Candidate descriptive strata may come from selected physical, chemical, astronomical, or biological sciences after metadata and sample review. Category names alone are insufficient; abstracts and source text need a frozen direct-exposure classifier and stratified manual audit.

### Rights

arXiv hosts items under several license choices. The default arXiv distribution license is not treated as a general corpus-reuse license.

The initial C design uses only item-level:

- CC0;
- CC BY.

The following are excluded until separately reviewed:

- default arXiv license;
- noncommercial terms;
- no-derivatives terms;
- share-alike terms;
- custom or missing licenses.

The metadata-only feasibility audit can occur before source retrieval. Bulk S3 source access is requester-pays and requires explicit authorization after storage and cost estimates.

### Holdout firewall

Before source-C confirmation, only the following may be inspected:

- metadata volume;
- timestamp/version fields;
- item-level license;
- category distribution;
- parser success;
- aggregate length and quality statistics;
- predeclared direct-exposure classifier outputs;
- a blinded manual sample for rights, version, and parser quality.

Do not inspect:

- source-C model behavior;
- source-C item-level behavioral direction;
- source-C examples for evaluation writing;
- source-C information for dose, threshold, hyperparameter, rescue, or mechanism selection.

### Main blockers

- metadata/full-text separation;
- requester-pays source retrieval;
- item-level license scarcity and distribution across categories/windows;
- latest-version versus historical-version integrity;
- direct exposure to evidence and method concepts;
- scientific event and field-composition drift.

### Qualification decision

**Qualified with redesign as provisional held-out C.** Continue metadata-only volume and license/version audit. Do not retrieve bulk source yet.

## Predeclared backup C — PMC Open Access

PMC is the backup, not a second source to tune against.

### Advantages

- item-level license metadata;
- structured JATS XML;
- approved API/OAI/FTP/cloud access paths;
- strong publication and article metadata;
- production process distinct from Wikimedia and Stack Exchange.

### Main problem

The current PMC XML object can include later corrections, replacement files, or updated deposits. It is not automatically the exact text available at the original publication date.

Promotion to source C requires:

- item-level CC0 or CC BY;
- original-version or no-later-update evidence;
- removal of third-party and supplementary components with different rights;
- exclusion of direct methods, statistics, clinical advice, policy, and behavioral constructs;
- deduplication against arXiv, preprints, abstracts, and journal versions.

### Qualification decision

**Candidate backup only.** It remains held out. Do not use it to tune the design if arXiv later fails; apply the predeclared backup criteria mechanically and document why the primary C failed.

## Rejected headline source — Federal Register/GovInfo

Federal Register and GovInfo data have excellent official timestamps and stable access, but they directly instantiate:

- central authority;
- safeguards and administrative procedure;
- transparency and secrecy;
- privacy and collective enforcement;
- punishment and rehabilitation;
- expert deference;
- dissent and public participation.

This makes direct imitation or topic exposure a dominant explanation for procedural outcomes.

Government hosting also does not make every embedded or transferred work public domain. Rights remain item/component-specific.

### Qualification decision

**Rejected from A/B/C.** Retain only as a later direct-exposure stress test or boundary control.

## Cross-source independence risks

The assigned sources are procedurally distinct, but not statistically independent in an absolute sense.

Potential common causes include:

- the same contemporaneous events;
- shared English-language culture;
- authors who participate on multiple platforms;
- quotations, citations, and copied text;
- external news and scientific sources;
- common search-engine and web vocabulary;
- broad platform demographic shifts;
- shared base-model pretraining overlap.

The project therefore needs:

1. exact and near-duplicate cross-source clustering;
2. citation/quotation stripping where practical;
3. contributor overlap analysis when privacy and identifiers permit;
4. event/entity concentration reports;
5. topic and register matching;
6. source-specific residual variance in the CSTG model;
7. source C prediction under a frozen component rather than treating C as an independent population sample.

“Independent source family” means independent intervention pipelines and substantially different production processes, not probabilistic independence of all text.

## Provisional era windows

The current candidates remain:

- early: 2012-01-01 through 2013-12-31;
- late: 2018-01-01 through 2019-12-31.

They are not frozen.

The final decision requires metadata estimates for every assigned source:

- eligible record and token volume;
- license distribution;
- version recoverability;
- source continuity;
- author/contributor concentration;
- topic and event concentration;
- quality/filter losses;
- direct-exposure exclusions.

A narrower one-year pair is preferred when it materially reduces event mixture without making A/B/C token sufficiency or license quality inadequate.

## Acquisition ladder

### Rung 0 — documentation and metadata

- official documentation;
- APIs and manifests that return metadata only;
- published dump inventories and checksums;
- no bulk text.

### Rung 1 — bounded development samples

- explicit page/post/article identifiers;
- small approved files or API samples;
- enough text to test parsers, timestamps, versions, licenses, and filters;
- no behavioral model training.

### Rung 2 — source-specific pilot manifests

- only after rights, storage, and parser gates;
- immutable locators and hashes;
- no complete 12-branch corpus.

### Rung 3 — matched naturalistic corpus

- only after synthetic calibration, evaluation reliability, and measured compute justify it;
- explicit user authorization for any nonzero access or storage cost.

## Acceptance criteria before source freeze

Every assigned source must demonstrate:

- sufficient eligible clean tokens in both windows;
- native timestamp confidence;
- historical version integrity;
- item-level rights and attribution feasibility;
- source-family independence analysis;
- direct-exposure exclusions;
- stable extraction and normalization;
- exact/near duplicate burden;
- topic, event, contributor, and length distributions;
- no use of model behavioral outcomes in source selection;
- storage and acquisition costs inside the authorized envelope.

Source C additionally requires the holdout firewall and a precommitted backup decision.

## Current decision

Proceed with **metadata-only and bounded parser samples** for the provisional A/B/C architecture. Do not bulk-download or train on any source yet.
